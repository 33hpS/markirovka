## 1. ОБЩИЕ СВЕДЕНИЯ

**"Маркировка"** - Автоматизированная система управления маркировкой продукции на производстве

- Учет продукции и партий

- **Разработка**: 6-8 недель

### 2.2. Выявленные проблемы

#### Архитектурные проблемы:
1. **Платформо-зависимость**
   - Привязка к Web API (Web HID/USB)
   - Невозможность работы на мобильных устройствах
   - Зависимость от браузера

2. **Производительность**
   - Canvas-рендеринг этикеток медленный
   - Нет кеширования данных
   - Отсутствие оффлайн режима

3. **Безопасность**
   - Все ключи в клиенте (Supabase anon key)
   - Нет шифрования локальных данных
   - Отсутствие audit log

#### Функциональные проблемы:

1. **Designer (Редактор этикеток)**
   - ❌ Нет сохранения шаблонов
   - ❌ Ограниченный набор элементов
   - ❌ Нет версионирования шаблонов
   - ❌ Отсутствует предпросмотр печати

2. **Production (Производство)**
   - ❌ Только mockup данные
   - ❌ Нет связи с реальными партиями
   - ❌ Отсутствует трекинг производства
   - ❌ Нет интеграции с оборудованием

3. **Printing (Печать)**
   - ❌ Нет очереди печати
   - ❌ Отсутствует учет расходных материалов
   - ❌ Нет истории печати
   - ❌ Не работает массовая печать

4. **Reports (Отчеты)**
   - ❌ Нет готовых отчетов
   - ❌ Отсутствует экспорт данных
   - ❌ Нет визуализации метрик

### 2.3. База данных (текущая)

**Существующие таблицы:**

```sql
-- Продукты
CREATE TABLE products (
  id UUID PRIMARY KEY,
  name TEXT NOT NULL,
  sku TEXT UNIQUE NOT NULL,
  price DECIMAL(10,2),
  category TEXT,
  description TEXT,
  manufacturer TEXT,
  weight TEXT,
  barcode TEXT,
  qr_data TEXT,
  status TEXT CHECK (status IN ('active', 'inactive', 'discontinued')),
  stock INTEGER DEFAULT 0,
  min_stock INTEGER DEFAULT 0,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  image_url TEXT
);

-- Шаблоны этикеток
CREATE TABLE templates (
  id UUID PRIMARY KEY,
  name TEXT NOT NULL,
  category TEXT,
  description TEXT,
  thumbnail TEXT,
  elements JSONB, -- Дизайн этикетки
  suitable_for TEXT[], -- Подходит для категорий
  version TEXT,
  is_active BOOLEAN DEFAULT true,
  author TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW()
);

-- Задания на печать
CREATE TABLE print_jobs (
  id UUID PRIMARY KEY,
  product_id UUID REFERENCES products(id),
  template_id UUID REFERENCES templates(id),
  quantity INTEGER NOT NULL,
  operator TEXT,
  printer_id TEXT,
  type TEXT CHECK (type IN ('direct', 'pdf')),
  status TEXT CHECK (status IN ('pending', 'completed', 'failed')),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  completed_at TIMESTAMPTZ,
  error_message TEXT
);

-- Пользователи
CREATE TABLE users (
  id UUID PRIMARY KEY,
  email TEXT UNIQUE NOT NULL,
  first_name TEXT,
  last_name TEXT,
  role TEXT CHECK (role IN ('admin', 'manager', 'worker')),
  status TEXT CHECK (status IN ('active', 'blocked', 'pending')),
  department TEXT,
  permissions TEXT[],
  last_login TIMESTAMPTZ,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  avatar_url TEXT
);
```

**Проблемы БД:**
- ❌ Нет таблиц для производственных партий (batches)
- ❌ Отсутствует история изменений (audit log)
- ❌ Нет таблицы для принтеров
- ❌ Отсутствует учет расходных материалов
- ❌ Нет связи продуктов с производством

## 3. НАЗНАЧЕНИЕ И ЦЕЛИ СИСТЕМЫ

### 3.1. Назначение

Система предназначена для **автоматизации процесса создания, управления и печати маркировочных этикеток** на производственных предприятиях.

### 3.2. Основные цели

1. **Управление продукцией**
   - Ведение электронного каталога продукции
   - Хранение информации о продуктах (SKU, штрих-коды, QR-коды)
   - Контроль остатков на складе

2. **Дизайн этикеток**
   - Создание шаблонов этикеток в визуальном редакторе
   - Версионирование шаблонов
   - Библиотека готовых шаблонов

3. **Производство**
   - Планирование производственных партий
   - Трекинг производственного процесса
   - Контроль качества
   - Учет произведенной продукции

4. **Печать этикеток**
   - Массовая печать этикеток для партий
   - Управление очередью печати
   - Поддержка различных принтеров
   - Учет расходных материалов

5. **Отчетность**
   - Производственные отчеты
   - Отчеты по печати
   - Аналитика по продукции
   - Экспорт данных

6. **Администрирование**
   - Управление пользователями и ролями
   - Права доступа
   - Аудит действий
   - Мониторинг системы

### 3.3. Целевая аудитория

1. **Операторы производственной линии** (роль: worker)
   - Сканирование продукции
   - Печать этикеток
   - Отметка о выполнении операций

2. **Менеджеры производства** (роль: manager)
   - Планирование партий
   - Контроль производства
   - Просмотр отчетов
   - Управление шаблонами

3. **Администраторы** (роль: admin)
   - Полный доступ ко всем функциям
   - Управление пользователями
   - Настройка системы
   - Мониторинг

### 3.4. Ключевые показатели эффективности (KPI)

- Сокращение времени создания этикетки: **с 10 минут до 2 минут**
- Уменьшение ошибок в маркировке: **до 0.1%**
- Увеличение скорости печати: **до 1000 этикеток/час**
- Прозрачность производства: **100% трекинг**

## 4. ТРЕБОВАНИЯ К СИСТЕМЕ

### 4.1. Функциональные требования

#### FR-1: Управление продукцией

**FR-1.1** Система должна позволять создавать карточку продукта с полями:
- Название продукта
- Артикул (SKU) - уникальный
- Штрих-код (EAN-13, EAN-8, Code 128)
- QR-код (данные для генерации)
- Категория
- Производитель
- Цена
- Вес
- Описание
- Изображение
- Остаток на складе
- Минимальный остаток
- Статус (активный/неактивный/снят с производства)

**FR-1.2** Система должна поддерживать CRUD операции для продуктов

**FR-1.3** Система должна иметь поиск продуктов по:
- Названию
- Артикулу (SKU)
- Штрих-коду
- QR-коду

**FR-1.4** Система должна поддерживать фильтрацию по:
- Категории
- Производителю
- Статусу
- Остаткам на складе

**FR-1.5** Система должна предупреждать о низком остатке товара

#### FR-2: Дизайнер этикеток

**FR-2.1** Система должна иметь визуальный редактор этикеток с элементами:
- Текст (поля продукта: название, SKU, цена, и т.д.)
- Штрих-код (генерация из данных продукта)
- QR-код (генерация из данных продукта)
- Изображение (логотип, фото продукта)
- Линии и рамки
- Произвольные фигуры (прямоугольник, круг)

**FR-2.2** Редактор должен поддерживать:
- Drag & Drop элементов
- Изменение размера элементов
- Выравнивание элементов
- Слои (порядок элементов)
- Группировку элементов

**FR-2.3** Шаблоны этикеток должны иметь:
- Название
- Категорию (продукция, упаковка, транспортная)
- Размер (ширина x высота в мм)
- Версию
- Автора
- Превью (миниатюра)
- Список подходящих категорий продуктов

**FR-2.4** Система должна сохранять версии шаблонов

**FR-2.5** Система должна иметь библиотеку готовых шаблонов

**FR-2.6** Система должна показывать предпросмотр этикетки с реальными данными продукта

#### FR-3: Производство

**FR-3.1** Система должна позволять создавать производственную партию (batch):
- Номер партии (автогенерация)
- Продукт
- Плановое количество
- Дата начала
- Дата окончания (плановая)
- Смена
- Линия производства
- Ответственный
- Статус (планирование → производство → контроль качества → завершено/отклонено)

**FR-3.2** Система должна отслеживать производство партии:
- Фактическое количество произведенного
- Процент выполнения
- Брак (количество и причины)
- Текущая операция
- История изменений статуса

**FR-3.3** Система должна поддерживать контроль качества:
- Проверка партии
- Фиксация результатов проверки
- Причины отклонения
- Повторная проверка

**FR-3.4** Система должна показывать дашборд производства:
- Активные партии
- Партии в очереди
- Партии на контроле
- Завершенные партии за период
- Общее количество произведенной продукции
- Процент брака

#### FR-4: Печать этикеток

**FR-4.1** Система должна позволять создать задание на печать:
- Выбор продукта
- Выбор шаблона этикетки
- Количество копий
- Выбор принтера
- Приоритет

**FR-4.2** Система должна поддерживать массовую печать:
- Печать для всей партии
- Печать для списка продуктов
- Печать с разными шаблонами

**FR-4.3** Система должна иметь очередь печати:
- Список заданий (ожидает → печатается → завершено → ошибка)
- Приоритизация
- Отмена задания
- Повтор при ошибке

**FR-4.4** Система должна поддерживать экспорт в PDF:
- Генерация PDF с этикетками
- Компоновка нескольких этикеток на листе
- Настройка размеров страницы

**FR-4.5** Система должна вести историю печати:
- Дата и время
- Оператор
- Продукт
- Количество
- Принтер
- Статус

**FR-4.6** Система должна управлять принтерами:
- Регистрация принтеров
- Статус (онлайн/оффлайн/ошибка)
- Модель и характеристики
- Расходные материалы (бумага, чернила)

#### FR-5: Оператор линии

**FR-5.1** Упрощенный интерфейс для работы оператора:
- Крупные элементы управления
- Минимум текста
- Быстрый доступ к основным функциям

**FR-5.2** Сканирование продукции:
- Поддержка USB/Bluetooth сканеров
- Сканирование через камеру устройства
- Распознавание штрих-кодов и QR-кодов

**FR-5.3** Быстрая печать:
- Сканировал продукт → автоматически печать этикетки
- Выбор количества
- Печать на ближайший доступный принтер

**FR-5.4** Отметка операций:
- Начало работы над партией
- Завершение операции
- Фиксация брака
- Передача на контроль качества

#### FR-6: Отчеты и аналитика

**FR-6.1** Производственные отчеты:

- Отчет по производительности линий
- Отчет по браку
- Отчет по выполнению плана

- Количество напечатанных этикеток за период

**FR-6.3** Отчеты по продукции:
- Движение товаров

- Популярные продукты

**FR-6.4** Экспорт отчетов:

**FR-6.5** Дашборды с визуализацией:

- Диаграммы по категориям

- Тренды

#### FR-7: Пользователи и права доступа

- Управление пользователями

```
│                                     │
└─────────────────────────────────────┘
```

#### Бизнес-логика

**Алгоритм входа:**
```
1. Пользователь вводит email и пароль
2. Валидация формата email
3. Проверка длины пароля (мин 8 символов)
4. Отправка запроса в Supabase Auth
5. Получение JWT токена
6. Сохранение токена в Secure Storage
7. Загрузка профиля пользователя
8. Проверка роли и статуса
9. Если статус = "blocked" → ошибка
10. Логирование входа в audit_log
11. Переход на главную страницу
```

#### Безопасность
- Пароли хешируются (bcrypt)
- JWT токены с коротким временем жизни (1 час)
- Refresh токены (7 дней)
- Ограничение попыток входа

```
UPDATE batches
SET
  produced = produced + {quantity},
  updated_at = NOW()
WHERE id = {batch_id}

// Проверка процента выполнения
progress = (produced / quantity) * 100

IF progress >= 100 THEN
  status = 'quality-check'
  completed_at = NOW()
  CREATE notification для менеджера
```

```
// При обнаружении брака

INSERT INTO defects (
  batch_id,
  quantity,
  reason,

  reported_at
) VALUES (...)

UPDATE batches
SET defect_count = defect_count + {quantity}
WHERE id = {batch_id}

// Проверка критического уровня брака
defect_rate = (defect_count / produced) * 100

IF defect_rate > 5% THEN
  CREATE alert:
```

```sql
CREATE TABLE products (
  -- Идентификация
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  sku VARCHAR(50) UNIQUE NOT NULL,

  -- Основная информация
  name VARCHAR(200) NOT NULL,
  category VARCHAR(100) NOT NULL,
  manufacturer VARCHAR(100),
  description TEXT,

  -- Цена и вес
  price DECIMAL(10,2) DEFAULT 0,
  weight DECIMAL(10,3), -- в граммах

  -- Маркировка
  barcode VARCHAR(50), -- EAN-13, Code128
  qr_data TEXT,

  -- Склад
  stock INTEGER DEFAULT 0,
  min_stock INTEGER DEFAULT 0,

  -- Статус
  status VARCHAR(20) CHECK (status IN ('active', 'inactive', 'discontinued')),

  -- Медиа
  image_url TEXT,

  -- Метаданные
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  created_by UUID REFERENCES users(id),
  updated_by UUID REFERENCES users(id)
);

-- Индексы
CREATE INDEX idx_products_sku ON products(sku);
CREATE INDEX idx_products_barcode ON products(barcode);
CREATE INDEX idx_products_category ON products(category);
CREATE INDEX idx_products_status ON products(status);
CREATE INDEX idx_products_name_trgm ON products USING gin(name gin_trgm_ops);

-- Триггер обновления updated_at
CREATE TRIGGER update_products_updated_at
  BEFORE UPDATE ON products
  FOR EACH ROW
  EXECUTE FUNCTION update_updated_at_column();
```

```sql
CREATE TABLE batches (
  -- Идентификация
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  batch_number VARCHAR(50) UNIQUE NOT NULL, -- BATCH-20260119-001

  -- Продукт
  product_id UUID NOT NULL REFERENCES products(id),

  -- Количество
  planned_quantity INTEGER NOT NULL,
  produced_quantity INTEGER DEFAULT 0,
  defect_count INTEGER DEFAULT 0,

  -- Производство
  production_line VARCHAR(50),
  shift VARCHAR(20) CHECK (shift IN ('first', 'second', 'night')),

  -- Даты
  planned_start TIMESTAMPTZ NOT NULL,
  planned_end TIMESTAMPTZ,
  actual_start TIMESTAMPTZ,
  actual_end TIMESTAMPTZ,

  -- Статус
  status VARCHAR(20) CHECK (status IN (
    'planning',
    'production',
    'quality-check',
    'completed',
    'rejected'
  )) DEFAULT 'planning',

  -- Ответственные
  operator_id UUID REFERENCES users(id),
  supervisor_id UUID REFERENCES users(id),

  -- Контроль качества
  qc_passed BOOLEAN,
  qc_notes TEXT,
  rejection_reason TEXT,

  -- Метаданные
  notes TEXT,
  created_at TIMESTAMPTZ DEFAULT NOW(),
  updated_at TIMESTAMPTZ DEFAULT NOW(),
  created_by UUID REFERENCES users(id)
);

-- Индексы
CREATE INDEX idx_batches_batch_number ON batches(batch_number);
CREATE INDEX idx_batches_product_id ON batches(product_id);
CREATE INDEX idx_batches_status ON batches(status);
CREATE INDEX idx_batches_operator ON batches(operator_id);
CREATE INDEX idx_batches_dates ON batches(planned_start, planned_end);
```

### 7.2. Row Level Security (RLS) политики

```sql
-- Включение RLS для всех таблиц
ALTER TABLE products ENABLE ROW LEVEL SECURITY;
ALTER TABLE templates ENABLE ROW LEVEL SECURITY;
ALTER TABLE batches ENABLE ROW LEVEL SECURITY;
ALTER TABLE print_jobs ENABLE ROW LEVEL SECURITY;
ALTER TABLE users ENABLE ROW LEVEL SECURITY;

-- Политика для продуктов
-- Admin и Manager: полный доступ
CREATE POLICY products_admin_manager ON products
  FOR ALL
  TO authenticated
  USING (
    EXISTS (
      SELECT 1 FROM users
      WHERE users.id = auth.uid()
      AND users.role IN ('admin', 'manager')
    )
  );

-- Worker: только чтение
CREATE POLICY products_worker_read ON products
  FOR SELECT
  TO authenticated
  USING (
    EXISTS (
      SELECT 1 FROM users
      WHERE users.id = auth.uid()
      AND users.role = 'worker'
    )
  );

-- Политика для пользователей
-- Admin: полный доступ
CREATE POLICY users_admin ON users
  FOR ALL
  TO authenticated
  USING (
    EXISTS (
      SELECT 1 FROM users u
      WHERE u.id = auth.uid()
      AND u.role = 'admin'
    )
  );

-- Все: могут видеть свой профиль
CREATE POLICY users_own_profile ON users
  FOR SELECT
  TO authenticated
  USING (id = auth.uid());
```

### 7.3. Функции и триггеры

```sql
-- Функция обновления updated_at
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
  NEW.updated_at = NOW();
  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Функция генерации номера партии
CREATE OR REPLACE FUNCTION generate_batch_number()
RETURNS TRIGGER AS $$
DECLARE
  date_part VARCHAR(8);
  seq_part VARCHAR(3);
  next_seq INTEGER;
BEGIN
  -- Формат: BATCH-YYYYMMDD-###
  date_part := TO_CHAR(CURRENT_DATE, 'YYYYMMDD');

  -- Получение следующего номера для сегодняшней даты
  SELECT COALESCE(MAX(
    CAST(SUBSTRING(batch_number FROM 16 FOR 3) AS INTEGER)
  ), 0) + 1
  INTO next_seq
  FROM batches
  WHERE batch_number LIKE 'BATCH-' || date_part || '%';

  seq_part := LPAD(next_seq::TEXT, 3, '0');

  NEW.batch_number := 'BATCH-' || date_part || '-' || seq_part;

  RETURN NEW;
END;
$$ LANGUAGE plpgsql;

-- Триггер генерации номера партии
CREATE TRIGGER generate_batch_number_trigger
  BEFORE INSERT ON batches
  FOR EACH ROW
  WHEN (NEW.batch_number IS NULL)
  EXECUTE FUNCTION generate_batch_number();

-- Функция логирования в audit_log
CREATE OR REPLACE FUNCTION audit_log_trigger()
RETURNS TRIGGER AS $$
DECLARE
  user_email_var VARCHAR(255);
BEGIN
  -- Получение email пользователя
  SELECT email INTO user_email_var
  FROM users
  WHERE id = auth.uid();

  -- Логирование
  IF (TG_OP = 'INSERT') THEN
    INSERT INTO audit_log (
      user_id,
      user_email,
      action,
      entity_type,
      entity_id,
      new_values
    ) VALUES (
      auth.uid(),
      user_email_var,
      'create',
      TG_TABLE_NAME,
      NEW.id,
      row_to_json(NEW)
    );
    RETURN NEW;

  ELSIF (TG_OP = 'UPDATE') THEN
    INSERT INTO audit_log (
      user_id,
      user_email,
      action,
      entity_type,
      entity_id,
      old_values,
      new_values
    ) VALUES (
      auth.uid(),
      user_email_var,
      'update',
      TG_TABLE_NAME,
      NEW.id,
      row_to_json(OLD),
      row_to_json(NEW)
    );
    RETURN NEW;

  ELSIF (TG_OP = 'DELETE') THEN
    INSERT INTO audit_log (
      user_id,
      user_email,
      action,
      entity_type,
      entity_id,
      old_values
    ) VALUES (
      auth.uid(),
      user_email_var,
      'delete',
      TG_TABLE_NAME,
      OLD.id,
      row_to_json(OLD)
    );
    RETURN OLD;
  END IF;
END;
$$ LANGUAGE plpgsql;

-- Триггеры аудита для ключевых таблиц
CREATE TRIGGER audit_products
  AFTER INSERT OR UPDATE OR DELETE ON products
  FOR EACH ROW
  EXECUTE FUNCTION audit_log_trigger();

CREATE TRIGGER audit_templates
  AFTER INSERT OR UPDATE OR DELETE ON templates
  FOR EACH ROW
  EXECUTE FUNCTION audit_log_trigger();

CREATE TRIGGER audit_batches
  AFTER INSERT OR UPDATE OR DELETE ON batches
  FOR EACH ROW
  EXECUTE FUNCTION audit_log_trigger();
```
